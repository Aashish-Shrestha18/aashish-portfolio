# Aashish Shrestha — Project Portfolio Website

A static, mobile-friendly portfolio built with HTML, CSS, JavaScript, SVG diagrams, project screenshots, and a downloadable two-page PDF resume. It is ready for GitHub Pages and requires no build step, npm install, paid website builder, backend, or API key.

## Publish with GitHub Pages

1. Sign in to GitHub and create a **new public repository**, for example `aashish-portfolio`.
2. Extract this ZIP file. Open the extracted `Aashish_Portfolio_GitHub_Pages` folder.
3. In the repository, choose **Add file → Upload files**. Upload all contents inside the extracted folder, including `assets/`. Commit to the `main` branch. Do not upload the ZIP by itself.
4. Open **Settings → Pages**. Under **Build and deployment**, choose **Deploy from a branch**, then select **main** and **/(root)**. Save.
5. When deployment finishes, open the **Visit site** link. The address usually follows `https://YOUR-USERNAME.github.io/aashish-portfolio/`.
6. Test the published site in a private/incognito window. Check the navigation, four project previews, image links, resume download, and email contact form before submitting the live URL to Brightspace.

Official GitHub Pages guidance:
- https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site
- https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Project case studies

The four projects use a consistent case-study structure: overview, personal contribution, process or technical focus, and outcome/reflection. Project status is identified where work is still in progress. The diagrams and screenshots are labelled according to what they show; the Right Drive image is a local form preview and the Taste Hub image is a desktop design concept.

## Before final submission

- Review each description to ensure the wording matches your exact individual contribution, especially for team projects.
- MobileLab is marked **in development**. The voice-support feature is described as planning/research, not as a completed or deployed feature.
- Taste Hub is described as a visual UX/UI concept, not a live ordering or reservation website.
- Add your real GitHub or LinkedIn profile URLs only if you want them displayed; none have been invented.
- Your professional email address is public on the website. Change it in `index.html` and `script.js` if you prefer a separate portfolio email.
- The contact form uses `mailto:` and opens the visitor's email application with a prepared message. It does not submit data to a server. The clickable email address is an alternative.
- Keep private customer, patient, API key, database, and teammate information out of public screenshots and repository files.
- The footer shows the author and last-updated date. Update the date when you make future changes.

## Preview locally

Double-click `index.html` to open the site in Chrome or Edge. The static website works without a local server. The contact form is best tested on a computer with a configured email application.
